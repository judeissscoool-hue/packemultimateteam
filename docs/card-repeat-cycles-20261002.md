# Exact-card repeat protection

New Classic Drafts roll the same rarity odds, then uniformly draw an eligible **card ID** that is not currently protected. There is no equal-player stage and no per-restart shuffled player list. Multiple card versions are separate tickets; offering one version does not protect another. Existing same-board and selected-squad player uniqueness remain.

Every offered card enters protection, including cards the user passes over. Bronze, Silver, Gold, Elite and Icon each have their own cycle. Once `ceil(poolSize * releaseFractions[rarity])` distinct IDs have been offered, the next offer from that rarity clears its protection and starts a new cycle. The October 3 policy uses **85% for Bronze, Silver, Gold and Elite, and 60% for Icon**. The pool is the complete available card pool for that rarity, not the discovered collection. The ordinary offer odds remain Bronze 14%, Silver 40%, Gold 40%, Elite 4% and Icon 2%; captain draws and selected-roster caps are unchanged.

A position can run out of unseen eligible cards before the whole rarity reaches its threshold. In that case, only the oldest currently eligible protected card is released. The already rolled rarity is retained. Empty rarity/position pools and selected Icon/Elite caps retain their earlier fallback rules.

Signed-in history persists across restarts, refreshes and devices, with separate Modern and True History pools. New `draft_fairness` snapshots are `{kind:'card-cycle-rarity-v1',releaseFractions:{Bronze:0.85,Silver:0.85,Gold:0.85,Elite:0.85,Icon:0.60},shown:[...]}`. The full map and shown IDs are immutable for that run. Existing scalar 0.75 and 0.90 snapshots retain their original policy and remain replayable. The selector emits ordered offer/reset/release events; the trusted handler replays the transcript before recording them. Idempotent cumulative checkpoints and a per-pool active-run cursor prevent duplicate recording and late older resets from clearing newer protection. Starting a replacement run flushes the previous transcript before taking its snapshot. The new policy uses the same history and does not clear prior protection; a rarity already past its new threshold resets when its next card is drawn.

An older run remains independently replayable. Concurrent runs do not reserve unrevealed future cards against one another; once a newer run becomes active, older new checkpoints do not mutate the current cycle. This matches the ordinary one-active-draft flow without applying stale reset events.

Guest and era drafts persist device history separately by roster pool and era using the existing `atu-card-cycle-v1` storage key. New states carry `rarityCardCycleDraft`, their secure random seed, word offset and `cycleReleaseFractions` map, so recreated local action factories continue the same sequence and policy. Older `cardCycleDraft` states retain their scalar `cycleReleaseFraction`; those missing the scalar field use their original 0.75 policy. Randomness uses the validated deterministic cryptographic generator with unbiased integer selection; no shuffled player orders are created.

New Modern starts use `atu-classic-v13`; True History uses `atu-history-draft-v11`. The scalar engines `atu-classic-v12` and `atu-history-draft-v10`, and all earlier versions, remain frozen for saved drafts. Pack Mode and Daily Challenge keep their rules. The trusted start handler supplies the complete 85%/60% map to the service-only `initialize_card_cycle_rarity` RPC, which retains the existing shared account cycles. The common `record_card_cycle` RPC accepts the new versions as well as the scalar versions. The versioned selector and immutable snapshot prevent a new policy from changing the replay of an existing run.

Tests cover exact-card rather than player frequencies, independent card versions, every rarity immediately below and at its 60%/85% boundary, ceiling rounding, position scarcity, unchanged rarity odds and caps, ordered shared history, restarts, cached boards, seven-pick restoration, account checkpoint retries, authentication, malformed policies, forged transcripts and all card versions. Frozen 75%/90% replay fingerprints and saved local-policy tests remain in place. Actual local starts and JSON-restored actions are compared with server replay; actual Edge handler tests mock authentication and database boundaries, with SQL checks handled separately.
